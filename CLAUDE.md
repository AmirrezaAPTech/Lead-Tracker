# CLAUDE.md

Project guidance for Claude Code working in this repo (`lead-cockpit`, Next.js 15 + Supabase).

## Environment files — HARD RULE

**Never modify, rewrite, reset, or overwrite `.env` or any `.env*` file. Do not touch them at all.**

This is the single most important rule in this repo. It applies unconditionally:

- **Never** replace real values in `.env` with placeholders, defaults, `your-key-here`, `xxx`, empty strings, or example values — not while editing, not while "cleaning up", not after finishing a task, not as a final tidy-up step.
- **Never** regenerate `.env` from `.env.example`, and never sync one into the other.
- **Never** delete, rename, truncate, or reorder `.env`, and never move it to a backup file.
- `.env` holds live working secrets. Anything written there by anyone other than the user destroys a working local setup and is not recoverable from git (`.env` is gitignored).

What to do instead:

- If code needs a new environment variable, **do not add it to `.env`**. Tell the user the exact variable name and what value it needs, and let them add it themselves.
- Add the new key to `.env.example` (placeholder value only) **only if the user explicitly asks for it** — otherwise just mention it in the response.
- Reading `.env` to check whether a variable exists is fine when it's needed for the task; writing to it is not. Never print secret values back into chat.
- If a task appears to require changing `.env`, stop and ask instead of editing.

## Commands

```bash
npm run dev        # Next.js dev server
npm run build      # production build
npm run typecheck  # tsc --noEmit
npm run lint       # next lint
npm run db:push    # supabase db push
npm run db:diff    # supabase db diff -f <name>
npm run db:reset   # DESTRUCTIVE: resets local db — confirm with the user first
```

## Layout

- `src/app/(app)` — authenticated app routes; `src/app/login` — auth; `src/app/api` — route handlers
- `src/components/ui` — shadcn/ui primitives (regenerated by the CLI; prefer wrapping over hand-editing)
- `src/components/lead` — lead-specific components
- `src/lib` — Supabase clients, helpers
- `supabase/` — migrations and local Supabase config

## Conventions

- TypeScript throughout; validate external input with `zod`.
- Tailwind v4 + shadcn/ui; compose classes with `cn()` from `src/lib`.
- After non-trivial changes, run `npm run typecheck` before reporting done.
